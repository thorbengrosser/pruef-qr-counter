# PRÜF Counter — ESP32

ESP32 firmware for a portable display that shows the live counter from the web API.

## Features

- Connects to up to 4 iPixel LED matrices via BLE (auto-discovers all `LED_BLE_*` devices and broadcasts to each)
- Polls `GET /api/count` from configurable URL
- Pre-rendered PNG frames (0–99) with optional flash animation
- **NVS config storage** — WiFi, API URL, poll interval saved in flash
- **Captive portal** — First boot or failed reconnect: AP "PRUF-Setup" / "pruef1234", configure at http://192.168.4.1
- **Web UI** — When connected, configure at http://&lt;device-ip&gt;/
- **Dual-SSID fallback** — Primary and optional secondary WiFi
- **BLE auto-reconnect** — Rescans and reconnects if display is lost

## Requirements

- PlatformIO (or Arduino IDE with ESP32 board support)
- ESP32 dev board
- iPixel 64×16 (or compatible) BLE display
- Python 3 + Pillow (for frame generation)

## Setup

1. **Generate PNG frames** (requires a TTF font; script defaults to `testing/Kario39C3Var-Roman.ttf` from repo root):
   ```bash
   # From repo root. If you don't have testing/, put a 64×16-suitable font (e.g. Kario) in esp32/tools/ and edit FONT_PATH in the script.
   python esp32/tools/generate_pngs.py [--flash-text-color RRGGBB] [--flash-bg-color RRGGBB]
   ```

2. **Compile-time defaults** — edit `include/config.h` (used when NVS is empty):
   ```c
   #define WIFI_SSID "YourNetwork"
   #define WIFI_PASS "YourPassword"
   #define API_URL "http://pruef.st/api/count"
   ```

3. **Build and flash**:
   ```bash
   cd esp32
   pio run -t upload
   ```

4. **Monitor**:
   ```bash
   pio device monitor -b 115200
   ```

## Configuration

- **First boot** or **no saved config**: Uses `config.h` defaults. If WiFi fails, starts captive portal after ~20s.
- **Connect to PRUF-Setup** (password: pruef1234) → open http://192.168.4.1 → enter SSID, password, API URL, optional fallback WiFi.
- **When connected**: Open http://&lt;device-ip&gt;/ to change settings (reboots on save).
- **WiFi lost**: Tries primary, then secondary, every 15s. After 8 failed cycles (~2 min), starts captive portal again.


## Protocol

- **BLE**: `LED_BLE_*` devices, UUID `0000fa02-...`
- **Image**: PIL-encoded PNG bytes
- **API**: `GET &lt;api_url&gt;` → `{ "count": N, "epoch": ... }`
- BLE rescans and reconnects if display is lost.
